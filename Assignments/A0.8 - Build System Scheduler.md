## Why

Topological sort is the algorithm behind build tools, CI pipelines, package managers, and workflow engines like Temporal or Airflow — a workflow is a DAG of activities that must execute in dependency order. This is the first assignment where an algorithm maps one-to-one onto your day job. Background: [[Algoritimos/Grafos/Teoria|Grafos — Teoria]].

## Brief

Create `dsa-from-scratch/06-build-scheduler/`. Input is a dict mapping a task to its dependencies (all must build **before** it):

```python
tasks = {
    "app":  ["lib", "lint"],
    "lib":  ["core"],
    "lint": ["core"],
    "core": [],
}
```

Implement:

1. **`build_order(tasks) -> list[str]`** — any valid topological order. Kahn's algorithm or DFS, your choice (be ready to defend it).
2. **Cycle detection with a clear error** — `ValueError("Cycle detected: app → lib → core → app")`. The message must show the actual cycle path, not just "cycle found". Also raise a clear error for an **unknown dependency** (a name that isn't a key) and **self-dependency**.
3. **`parallel_batches(tasks) -> list[list[str]]`** — BFS levels: level 0 is tasks with no dependencies; each task lands in the first level after all its dependencies. Tasks in the same batch can build concurrently. For the example: `[["core"], ["lib", "lint"], ["app"]]`.

Tests: linear chain, diamond (`app → [lib, lint] → core`), independent groups, disconnected single task, cycle across 3+ nodes, self-dependency, unknown dependency, empty input.
