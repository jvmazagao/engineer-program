# A6.1 — Project One-Pager

## Why

Promotion panels don't grade effort; they grade framed, delivered, measured impact. The one-pager is where a vague pain becomes a project with a number attached — before a single line of code is written.

## Brief

Pick the senior-scope project you'll run for phase 6. Per the phase note, a good candidate is: **ambiguous** (problem clear, solution isn't), **impactful** (revenue, cost, reliability, customer pain, developer velocity — measurable), **broad** (touches more than one component or team), **1–3 months long**, and **visible** (leadership cares). Look at recurring incidents, top customer complaints, slow dev workflows, cost spikes, tech debt blocking the roadmap.

Write **one page, no more**:

1. **Problem** — with a number: cost, tickets, minutes, incident count
2. **Impact metric** — how we'll know it worked, with the baseline captured *before* starting
3. **Scope** — what's in
4. **Non-goals** — what's explicitly out; should disappoint someone
5. **Milestones** — 3–5, each delivering standalone value (no "phase 2 makes it useful")
6. **Risks** — top 3 with mitigations
7. **Who** — you + who else, even if it's just reviewers

Get **written sign-off** from your manager and the key affected stakeholder. If you can't get the impact metric agreed, the project isn't ready — iterate the one-pager, not the project.

## Tasks

- [ ] Shortlist 2 candidate projects; pick one with mentor input (ambiguity + impact + breadth)
- [ ] Write the one-pager: all seven sections
- [ ] Capture the impact-metric baseline before any work starts
- [ ] Pre-wire: informal read with the stakeholder before formal sign-off
- [ ] Get written sign-off from manager + key stakeholder
- [ ] Add the project to the Brag Document

## Acceptance criteria

- [ ] One page, all seven sections present
- [ ] Problem and impact metric both carry numbers; baseline captured before starting
- [ ] Non-goals would genuinely disappoint someone
- [ ] Written sign-off from manager and key stakeholder
- [ ] Every milestone delivers standalone value

## Rubric (1–4)

| Criterion | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| Problem | Vague pain | Real but unnumbered | Numbered with a baseline | Also shows why now, and why you |
| Impact metric | Activity metric ("migrate X") | Outcome metric, no baseline | Outcome metric + baseline | One the stakeholder would quote to their boss |
| Scope | Everything is in scope | Non-goals listed but soft | Hard non-goals | Anticipates the mid-project scope attack |
| Sign-off | Verbal only | Manager only | Manager + stakeholder in writing | The stakeholder would notice within a week if the project stalled |
