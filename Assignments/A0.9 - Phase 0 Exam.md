# A0.9 — Phase 0 Exam

## Why

Phase 0 ends with proof, not vibes: solve something unseen, catch a real complexity bug in code that looks innocent, and answer the fundamentals cold. This is the gate before Phase 1 starts building on all of it.

## Brief

A 60-minute pairing session. **Mentor = examiner, engineer = candidate.** Pass bar: **average score ≥ 3** across the three parts.

**Part 1 — Unseen Medium (≈ 30 min).** One Medium problem from any weeks 2–11 topic, verified against the engineer's pattern journal (peer + mentor check beforehand). Think aloud; hints allowed but recorded and they lower the score.

**Part 2 — Find the complexity bug (≈ 15 min).** Mentor brings a 30–80 line snippet that *looks* production-ready but hides an accidental O(n²) — membership test on a list inside a loop, string concatenation in a loop, repeated slicing, an N+1-ish lookup. The engineer must: read it, name the bug, state actual vs intended complexity, and propose the fix.

**Part 3 — Five rapid questions (≈ 10 min).** ~30 seconds each, no whiteboard:

1. Why is `list.append` O(1) *amortized* rather than always?
2. When does a hash map lookup degrade to O(n), and what input causes it?
3. Why can no comparison-based sort beat O(n log n)?
4. BFS or DFS for shortest path in an unweighted graph — and why?
5. Is your language's builtin sort stable? Which algorithm is it based on?

**Scoring:** each part scored 1–4 per the rubric; average across all rows decides pass/retake. Below the bar → targeted practice on the weakest row (mentor names it) and a retake in 2 weeks with fresh material.

## Tasks

- [ ] Send pattern journal index to mentor ≥ 48 h before (for problem vetting)
- [ ] Mentor prepares: 1 unseen Medium, 1 buggy snippet, question list
- [ ] Hold the 60-min exam
- [ ] Think aloud in Part 1; find and fix the bug in Part 2
- [ ] Record per-row scores, average, and pass/retake in the submission note
- [ ] If retake: schedule within 2 weeks with new material

## Acceptance criteria

- [ ] All three parts completed inside 60 minutes
- [ ] Every rubric row scored with a recorded average
- [ ] Part 2: bug named, wrong complexity stated, fix proposed — at least identified even if fix is rough
- [ ] Pass/retake decision recorded against the ≥ 3 bar
- [ ] Weakest row named with a concrete follow-up action

## Rubric (1–4)

| Criterion | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| Problem solving | No working approach | Brute force only or needed many hints | Working solution with a named pattern | Clean solution, correct complexity, tested |
| Bug hunt | Bug not found | Found but complexity wrong | Bug + complexity right | Bug + complexity + minimal fix, explained |
| Rapid answers | Under 2 of 5 | 2–3 of 5, shaky | 4–5 of 5, brief and correct | 5 of 5 with one-line reasons, not memorized |
| Communication | Silent or rambling | Thinks aloud inconsistently | Steady narration, mentor always informed | Narrates trade-offs and self-corrects out loud |
