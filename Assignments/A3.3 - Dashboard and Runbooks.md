# A3.3 — Dashboard and Runbooks

## Why

The artifact that proves ownership isn't the code — it's whether a stranger can keep your service alive at 3am. Dashboards you read fine and runbooks only you can follow are indistinguishable from having neither.

## Brief

Two artifacts for a real service you own.

**1. The dashboard.** One screen, ordered top-to-bottom the way an on-call reads it:

1. SLO status / error budget (from A3.2)
2. RED per flow
3. Saturation signals (DB connections, queue depth, memory)
4. Recent deploys and events overlay

A new on-call must answer *"is it healthy, and if not, which flow?"* in 30 seconds. No chart that nobody would act on.

**2. The runbooks.** For the top 3 paging alerts of the last 90 days (or best available data). Each runbook:

- What the alert means **in user terms**
- First 3 checks, with exact queries/commands/links — no "check the logs" hand-waving
- Mitigation steps, copy-pasteable
- Escalation path, including "if all else fails"

**The test.** Hand runbook #1 to a peer who doesn't know the service. Give them a fake firing alert or a staging simulation, and watch silently. Every place they get stuck is a defect in the runbook. Fix what breaks.

## Tasks

- [ ] List the alerts that paged in the last 90 days; pick the top 3
- [ ] Build/rebuild the dashboard: SLO → RED per flow → saturation → events, one screen
- [ ] Write 3 runbooks with exact commands, queries, and working links
- [ ] Peer test: a peer attempts runbook #1 under simulation; you observe without helping
- [ ] Fix every friction point; note what you'd assumed only an owner knows
- [ ] Link dashboard + runbooks from the service README and from the alert configs

## Acceptance criteria

- [ ] Peer test proves a stranger answers "healthy? which flow?" in ≤30 seconds
- [ ] No vanity charts on the dashboard
- [ ] 3 runbooks exist; every mitigation step is copy-pasteable
- [ ] Peer test done with someone outside the service; ≥3 friction points found and fixed
- [ ] Alerts link to their runbooks; README links both

## Rubric (1–4)

| Criterion | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| Dashboard | Vanity metrics | Complete but cluttered | 30-second readable | A stranger diagnosed the right flow unaided |
| Runbook depth | "Check the logs" | Steps exist but vague | Exact queries and commands | Includes what *not* to do and when to escalate |
| Peer test | Not done | Done, peer nods along | Real friction found and fixed | The test materially changed the artifact — proof it wasn't theater |
| Adoption | Lives in personal notes | Linked somewhere | Linked from alerts + README | Team adopted it as the template for other services |
