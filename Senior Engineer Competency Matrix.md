# Senior Engineer Competency Matrix

← [[Mid to Senior Engineer Roadmap]]

**How to use:** score each row 1–4 monthly. Ask your manager or mentor to score you too, independently, and discuss where you disagree. Focus on the 2 lowest rows each month.

Scale: **1** rarely · **2** with help · **3** independently, usually · **4** consistently, and others learn from me

## 0. CS fundamentals

| Behavior | Mid | Senior | Score | Evidence |
|---|---|---|---|---|
| Complexity | Code works, cost unclear | States time/space cost; spots accidental O(n²) and N+1 | | |
| Data structures | Uses lists and dicts for everything | Picks the right structure (set, heap, tree, queue, graph) on purpose | | |
| Algorithms | Looks up solutions | Recognizes patterns (search, sort, BFS/DFS, DP) and implements them | | |
| How computers work | Fuzzy | Explains memory, processes/threads, binary/floats when debugging | | |

## 1. Technical depth

| Behavior | Mid | Senior | Score | Evidence |
|---|---|---|---|---|
| Debugging | Fixes bugs with guidance on hard ones | Diagnoses unfamiliar, cross-system issues from first principles | | |
| Performance | Fixes obvious inefficiencies | Profiles, measures, explains root cause | | |
| Fundamentals | Knows the framework | Knows runtime, DB, network behavior underneath | | |

## 2. System design

| Behavior | Mid | Senior | Score | Evidence |
|---|---|---|---|---|
| Ambiguity | Needs a defined spec | Turns vague problems into a design | | |
| Trade-offs | Picks one approach | Compares options, documents why | | |
| Failure modes | Handles happy path | Designs for partial failure, retries, idempotency | | |
| Evolution | Solves today's need | Anticipates change without over-engineering | | |

| Behavior | Mid | Senior | Score | Evidence |
